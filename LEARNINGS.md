# Fleet Runner lessons

- A registered run's --source override changes the files, not the registered recipe. Qualify a changed recipe from a worktree with one-time submit using its full manifest. Packaging profiles must include every input the packager reads, including LICENSE and LICENSING.md; checking source alone missed the latter input until a real worker build exercised it.

- Diagnose a missing log tail by comparing the controller log, retained worker log and producer's own saved report. Equal worker/controller bytes locate loss before collection. On POSIX, Node writes to pipes/FIFOs asynchronously: writableNeedDrain=false does not prove queued writes completed before process.exit. An Nx 23.3.1 probe lost the tail of an 11,008-byte FIFO write at exactly 8,192 bytes; awaiting the write callback preserved it. Fix producer completion rather than adding timed padding or assuming receipt success proves a complete console report.

- Saved runs, one-time submits and external reservations must share automatic load-aware worker selection. This supersedes default-first placement: the saved default only breaks equal load comparisons, resolving a valid alias to its canonical entry. Count current coordinator leases synchronously just before admission because live CPU/memory observations can lag simultaneous clients. An explicit worker list and a project's worker pin remain binding. Prefer a worker before admission; never replay a failed or uncertain admitted job on another machine.

- Native-notification tests must inject an explicit recorder or no-op sender. A PATH substitute is not safe isolation: a local Node launcher can prepend real tool directories and bypass the fake sender. The installed-wiring probe produced a real fixture banner; direct sender injection removed that path.

- Disk alerts belong to actual operations and typed causes, not generic busy errors or state polling. Keep one sender attempt across worker skips and later archive failures; notification failure must not change job results. Preserve a typed free-space cause across both streamed completion and stale archive capture, while ordinary USB size routing stays quiet.

- A Docker VM has its own disk budget. Host free-space admission can pass while Colima's container-data filesystem is full; inspect the guest filesystem and its actual host backing path. External returned-artifact storage does not establish where Docker data lives. Supported Colima disk growth needs a stopped VM, so coordinate the existing stack owner's guarded export/stop first, preserve volume identities, then verify the effective guest filesystem and Docker after startup. A larger YAML value alone is not proof of usable space. The normal restart may also reclaim host blocks already free inside the VM; do not infer a need to delete datasets from the host's allocated image size.

- Large temporary files should use a private worker destination only for a real sequential consumer. The output archive writer is shared by internal and external storage; uploads stream directly. Pin and verify the mount's UUID/device before creation, use no-follow descriptors for writes/reads/deletes, and keep hot source/cache/TMPDIR/Docker paths internal. Per-job tokens and ACK-aware cleanup preserve uncertain or unacknowledged output. Concurrent APFS O_CREAT may report ENOENT while the other creator's inode exists; create a permanent guard exclusively or open that exact existing inode without deletion, timed retries or path fallback.

- Recognize CLI help before state validation, service startup or any command side effect, including reservations and service installation. Share the check with the internal dispatcher; stop recognizing Fleet flags at `--` so profile help still reaches its command. Verify real CLI help makes zero socket requests, including through the legacy alias.

- A submit worker selector must be parsed before service startup and mapped explicitly to its API field. Use the shared closed argument parser so singular pins, ordered lists, equals syntax, repeats, missing values and unknown options cannot silently become default worker selection. Exercise the real CLI-to-socket request, not only API selection.

- Stale-lock deletion and new-job admission must share a kernel guard. Checking a removable lock twice does not make it atomic: another clearer can delete a new owner's lock after an earlier stale observation. Keep the admission inode permanent. Verified by an overlapping-cleanup probe and lifecycle regression.
- A successful test result is only one phase. Preserve later connection/artifact errors and require confirmed lock release before a passed receipt. A dropped RELEASED/BYE regression proves this boundary.
- Artifact limits use logical file bytes, including sparse files, and a hard archive-file limit. Allocated blocks undercount tar expansion. Every required artifact needs verified returned content and every regular file needs an expected remote hash.
- Arm artifact capture before reading the supervisor stream: RESULT, archive header and bytes may arrive in one SSH chunk before an awaited continuation runs.
- Profile scratch can be directly under JOB_DIR, not only src/tmp. Clean every owned child except an explicit small evidence/control list after its processes exit and artifacts return. Do not let DerivedData survive as retained logs.
- Uploaders need separate lifecycle ownership: they use a second SSH connection outside the test process group. A per-job kernel transfer guard, terminal-state check and receiver cancellation prevent cleanup racing a still-writing or delayed upload.
- Do not import uploaded Python source during an in-progress transfer. Even a help/diagnostic command can generate __pycache__, and the exact input-count check correctly rejects that altered snapshot. Use -B for read-only probes or run them outside the source snapshot.
- macOS Bash 3.2 read timeout and EOF both return status 1. The separate control reader explicitly records EOF so disconnection stops a job without confusing an ordinary polling timeout.
- Better Git's test host needs short temporary paths for macOS IPC sockets. Leave isolatedTmp false and use its disposable Mini-only fixture workflow. Do not set its MacBook placement flag.
- Detached resources require a finite, idempotent, ownership-checked profile finalizer. Run it after the job group stops and before capture/deletion, including explicit stale recovery; failure retains source and ownership. Keep the admission and per-hook guard in the hook's children too.
- Artifact ACK means verified extraction, hashes and complete declared outputs. EOF and NACK retain the bounded archive and original hash declaration; recovery verifies again before remote deletion. Refuse new jobs at the pending archive cap instead of rotating the only result away.
- Keep machine/project configuration separate from large returned artifacts. The explicit run-directory override requires an existing absolute .noindex directory, so a missing external scratch mount cannot cause an invented mount directory or silent local fallback.
- Successful stale finalizer recovery is also an artifact-capture boundary: the hook may only then prepare its reports. Use the shared bounded capture before scratch deletion, retain source/ownership if it cannot capture all declared outputs, and reuse an existing pending archive on repeated clears. A first-failure → retry-success → verified-recovery regression preserves the original failed result and receipt. Keep ordinary unverified-return archive retention intact when hash collection fails; the stricter stale-capture error must not change normal-return cleanup semantics.
- Ordered worker selection may advance only after read-only refusal or a conclusive BUSY admission. A nonzero run result is not retry permission: admission or an uncertain reply fixes the worker choice. Compare physical fingerprints, including the dispatching computer, rather than trusting registry names alone.
- Rsync needs an independent local input copy. Hardlinks change when an editor rewrites the original inode and can let rsync read beyond the planned size. Reuse the bounded hash-checked tar reader for staging, then recheck the original before starting the job. Reclaim abandoned staging only after every recorded local owner is gone, preserving logs and results.
- Apple openrsync splits its remote-program string and can alter nested quoting. Pass a fixed program placeholder through rsync and give the existing SSH adapter the already quoted receiver command. Keep receiver scripts in disposable job metadata, as with the finalizer, never in retained source caches.
- Crafted tar fixtures need the same macOS metadata suppression as production archives, including append calls. An M1 Max run returned an unexpected `._dir` member before reaching the intended symlink-traversal assertion; `--no-mac-metadata` and `COPYFILE_DISABLE=1` preserved the intended check.

- A local coordinator must have process-lifetime kernel ownership, including concurrent CLI auto-starts. The Python wrapper and Node child both hold the permanent flock descriptor; never unlink that inode. Six simultaneous clients and stop/start were verified.
- Use short-lived HTTP connections for the local API. Reusing a keep-alive connection can make a stopped service appear reachable through an old socket, invalidating restart checks. The singleton regression covers this.
- External reservation expiry is uncertainty, not evidence of stopped work. Preserve ownership on expiry/restart and require a fresh idle observation plus the token for release. Managed crash recovery may clear only its own verified-idle reservation.
- Keep private project adapters and retired-worker guidance outside the generic package. Preserve legacy CLI and protocol names as compatibility paths while the new name delegates to one coordinator.
- A dashboard must never become another client's heartbeat. The desktop app polls operations with `observe=1`, and runs it starts are `detached`, so viewing abandoned work still lets it be cancelled while quitting the app cancels nothing. Verified by the detached/ordinary/observed run regression.
- An app opened from the Dock has no shell PATH, nvm or THE_FLEET_HOME. The login service plist records the exact Node, CLI script and state folder the service uses, so discovery prefers it after explicit app settings and only then searches installed commands. Starting the service goes through the CLI's kernel-locked auto-start, never a second launcher.
- ImageRenderer draws no AppKit-backed scroll view on macOS, even with a fixed height. Headless screen tests lay content out inline through `FleetScroll`'s environment flag; List rows are rendered individually. Four whole-screen renders were blank before this and draw after it.
- Revalidate worker destinations after an awaited probe, immediately before granting external ownership. A settings save or removal can finish while that probe waits; the same destination check protects managed runs and reservations. Deferred-probe regressions cover changed routes, changed roots and removed workers.
- A changed desktop connection invalidates pending results, errors, navigation and polling bookkeeping. Cancelling a Swift task alone does not cancel its blocking Unix-socket read; generation checks keep old replies out of the new connection. Delayed health and state tests reproduce the boundary.
- A recovery control on one worker must pass that worker through to the coordinator. Keep the existing global API available for callers explicitly recovering the whole fleet; never silently expand a per-worker action to other reservations.

- Foreground automatic maintenance requires both coordinator ownership and the existing remote kernel guard. Keep state discovery read-only; protect active, expired and restarted reservations, recheck the exact marked stale job under the guard, and retain uncertain cleanup ownership. A resident-memory snapshot and historical swap use are diagnostic evidence, never proof of a leak or permission to stop arbitrary work.
- A full one-time manifest should use parseManifest and the existing planView/planRun rather than recreating profile fields or digest logic. Stable manifest.id preserves the existing per-project rsync source identity without changing shared cache semantics; keep CLI status/receipt prefixes consistent across registered and one-time routes.
- An rsync progress line can precede the process itself. Two 3,936/4,149-file jobs spent roughly ten minutes before remote execution while sampled controller threads were reading completed SD staging files. Hash the original as it is copied, rely on the receiver's exact manifest check for staged bytes, and recheck the live source before permitting execution. Report these phases separately. Keep run-store I/O off the coordinator's request thread and bound log-tail reads, because a slow external results volume must not stop other clients polling. A delayed receipt-read regression covers concurrent health, state and operations requests.
- Client adapters that validate the public receipt must accept the typed `aborted` outcome. A source-change stop returns exit 2, a receipt and no started job. The AIMVS watch had an older closed enum and surfaced a parser error instead of the source-change reason. Fix the adapter and preserve the Fleet receipt classification.

- Cancel API retries must be idempotent. Preserve the CLI's deliberate second Ctrl-C through an explicit forceDisconnect request; handle a force request arriving before an ordinary cancellation and keep later repeats from adding signals. Real CLI-signal and API regressions cover this boundary.
- A shared cache can be under its size limit yet lack space for rsync's retained source plus replacement reserve. Use bounded disposable job source in that case, retaining the same verification and upload guard; never evict dependencies or another project to make source fit. An already-over-limit non-concurrent cache still refuses safely. Explicitly concurrent caches may remain over their retention cap while a neighbour uses them: use disposable source instead of refusing, and tolerate vanished dependency entries only during approximate cache measurement. Source verification remains strict.

- Shared worker capacity needs two kinds of ownership: kernel reader/writer admission plus inherited bounded slots/resources, and per-job owner records. Legacy exclusive work must keep taking the same permanent admission inode. Deduplicate remote owner records against preallocated coordinator job IDs when reporting/admitting capacity; unknown records still consume a slot. Never classify a stale/orphaned PGID as verified managed CPU work.
- Cache access, mutable source sync and retention have different lifetimes. Serialize source sync/materialization per cache/project, allow proven concurrent cache tools to overlap, and protect eviction with cache usage guards plus recorded cache claims. Children can close inherited extra file descriptors, so a surviving orphan's owner record must also prevent eviction. Keep access/usage lock roles in disjoint hashed namespaces. Exact-job controls must refuse a missing target instead of falling through to a neighbour.
- A pre-session failure needs explicit never-started proof. A busy neighbour prevents whole-worker idle recovery but does not mean the refused run started; release only that proved-never-started lease. After a session is attempted, retain the conservative remote verification boundary.
- Shared owner directories already carry their preallocated job IDs before owner files exist. Preserve that identity in startup observations and ignore vanished/free records to avoid double-counting a managed lease. CLI status and native worker derivations must consume shared records, match cancellation by job ID, and keep activity separate from the coordinator's availability decision.
- Returned files need their archive mtimes restored after hash verification through the already-open output descriptor. Fresh extraction times destroy ordering used by consumers such as Playwright's last-failed profile selection. Honor per-file and global PAX mtime overrides, including an empty per-file override and pre-epoch fractional values; Node numeric strings avoid its negative-number-to-now conversion. Keep path, symlink, size and hash checks intact and share this behavior with artifact recovery.

- PAX fixtures must give an empty per-file mtime override a known classic header. Python 3.9's writer zeroes that header when PAX mtime is present, while Python 3.13 retains the original time. Preserve a stdlib-generated USTAR header for that fixture instead of changing correct extraction to satisfy different generated input. Check tool versions inside the actual profile shell: login-shell PATH can differ from preflight.

- A state-home migration must coordinate with both the permanent service inode and concurrent launchers. Resolve old default-home callers through one completed migration record, refuse incomplete/conflicting homes, and open startup logs only after the parent guard. An atomic rename preserves receipt bytes and inodes; rewrite only mutable pointers. Verify the live inventory, settings and ownership as well as byte hashes and inode identity; legacy callers must reach the same migrated coordinator.
- Shared returned-results settings need an independent revision and per-operation capture. New jobs re-read the preference; admitted jobs keep their destination. A missing external drive must block writes without hiding Settings. Native save failures and connection changes must retain the correct server state and never silently redirect a run.
- An exit code is not an outcome. A source-change stop shares exit 2 with usage errors, and a crash exits 1 like a failing test. That made protective stops look like Fleet errors. Record the typed outcome (`aborted` plus `abort.path`) in the receipt and index, and have operations report it. Clients then read one classification instead of re-deriving it. Older records are reinterpreted only from exact evidence: the unchanged message without a cleanup note, a confirmed release and no job start. Keep the stored receipt unchanged; unconfirmed cleanup stays an error. Mark a pruned index explicitly when classifying it: a full receipt missing evidence is damaged, not deliberately shortened history.

## Signed app updates (2026-11-05)

- Embed Sparkle.framework in Contents/Frameworks and add @executable_path/../Frameworks to the executable rpath. Verify the final bundle with --check-packaged-launch; a successful Swift link and codesign verification alone do not prove it loads.
- Ad-hoc test packages must not enable hardened-runtime library validation. Developer ID release signing re-signs Sparkle's nested helpers, then its framework and the outer app with the same identity and a timestamp.
- Release signing accepts only the CI archive whose SHA-256 and source commit match its receipt. Apple must accept notarization, and the final archive must retain a validated stapled ticket before generating the signed feed. Signing keys remain in Keychain.
- Sparkle updates only the desktop client. Its lifetime is separate from the shared coordinator and detached jobs; do not restart or replace that service during an app update. Check for Updates is distinct from the Fleet menu's worker-refresh Check Now.

## 2026-11-05 — Reuse checksum-verified release signing tools

Release workflows invoke the signing host's versioned Sparkle copy at `~/.local/share/sparkle-tools/2.10.1/bin`, after comparing it with the freshly downloaded, checksum-verified SDK. Provision this directory during signing-host setup; a missing or mismatched copy blocks signing instead of invoking an unverified or disposable helper. Keep per-app Keychain accounts and public-key checks. Reusing identical tool bytes does not promise approval survives a tool upgrade or a changed key.

## 2026-11-06 — Independent ordinary and E2E ceilings

A whole-ship external reservation can report zero free capacity while consuming only one ordinary slot. Raising slot limits cannot bypass that deliberate exclusive claim. Classify browser/E2E work once from explicit metadata or known command/profile tokens (including extra CLI arguments), and carry that decision through coordinator reservations, preflight and remote kernel admission. E2E work takes both an ordinary slot and a separate E2E slot; old unknown managed records count conservatively for the E2E ceiling. Keep expiry as uncertain ownership, not automatic proof of cleanup.
